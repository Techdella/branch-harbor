# Translation glossary

Shared terminology for every BranchHarbor surface: marketing site (`apps/web`), business app (`apps/app`), customer
websites (`apps/sites`) and mobile app (`apps/mobile`). Use these terms in new strings so a business owner sees the
same word on the website, in the app and on their phone, and their customers see the same word on the site and in
the app.

## Languages and tone

| Locale | Used by | Register | Notes |
| --- | --- | --- | --- |
| `en` | all | Friendly, direct | **US English** (authorized, canceled, organization, program, inquiry, fulfill, color, postal code). |
| `en-GB` | web, sites | Same as `en` | British spelling (authorised, cancelled, organisation, programme, enquiry, fulfil, colour, postcode). |
| `fr` | all | *vous* | Typographic apostrophe (’), non-breaking space before `: ; ? !` and `%` is optional — keep consistent within a screen. |
| `es` | all | *tú* | Neutral international Spanish (no *vosotros*). |
| `de` | all | *Sie* | Nouns capitalised; prefer short compounds for buttons. |
| `pt-BR` | all | *você* | Brazilian vocabulary (cardápio, celular, agendamento). |
| `nl` | web, sites | *je* | |
| `it` | web, sites | *tu* | |
| `ar` | web, sites | Modern Standard Arabic | Right-to-left; see [RTL rules](#arabic-and-right-to-left). Brand and person names stay in Latin script. |

Business content (names, addresses, menus, class names, listing text) is shown as the business published it and is
never machine-translated. Only UI text is translated.

## Money, numbers, dates

* Amounts are integer minor units plus an ISO currency and are always formatted with `Intl.NumberFormat` in the
  viewer's locale. Never write a currency symbol or decimal separator into a message: pass the formatted amount as an
  argument (`{amount}`).
* Totals in different currencies are shown per currency and never added together ("shown per currency").
* Dates and times use `Intl.DateTimeFormat` with the active locale and the location's IANA time zone; show the zone
  label next to location times. Don't put a fixed format (`MM/DD`, `9:00 AM`) in a message.
* Plurals use ICU (`{count, plural, one {…} other {…}}`) in the web, app and sites catalogues and i18n-js
  `{ one, other }` objects on mobile. Arabic uses the full set (`zero`, `one`, `two`, `few`, `many`, `other`) where a
  count is shown.

## Arabic and right-to-left

Customer websites serve Arabic (`ar`) with `dir="rtl"` on `<html>`:

* Layout uses logical properties only (`ms-*`/`me-*`, `ps-*`/`pe-*`, `start-*`/`end-*`, `text-start`/`text-end`,
  `border-s`/`border-e`), so it mirrors automatically.
* Directional icons (back/next chevrons, arrows, send, undo, log out) flip with `rtl:-scale-x-100` — `@bh/ui`'s
  `Icon` adds it automatically; icons that are not directional (search, clock, check) don't.
* Prices from `lib/format.ts` `money()` are isolated (FSI…PDI) in right-to-left locales. Addresses and Latin names are
  wrapped in `<bdi>`; phone numbers get `dir="ltr"`; truncated Latin brand names use `dir="auto"` so the ellipsis
  lands at their end.
* Arrows inside sentences are written as ← in Arabic (reading direction), e.g. "الفرع ← القائمة".

## Text that comes from the API

Sentences the API composes (studio cancellation policy, membership terms, error messages) are English. Where the API
also returns the facts behind them — e.g. the studio policy's `terms` — sites and mobile phrase them from the
catalogue (`studio.terms.*`) and only fall back to the English lines for older responses.
